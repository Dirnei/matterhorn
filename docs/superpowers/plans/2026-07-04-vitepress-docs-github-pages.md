# VitePress Docs Site + GitHub Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **EXECUTION LOCATION:** This plan MUST be implemented in an isolated git worktree (user requirement), created via superpowers:using-git-worktrees before Task 1. All commands below run from the worktree root.

**Goal:** Publish a VitePress documentation site for Matterhorn on GitHub Pages, built from the existing README content, with the README slimmed to a pitch + link.

**Architecture:** VitePress rooted at `docs/` (internal `docs/superpowers/**` excluded from the build). Content is a restructure of the README into guide pages. A dedicated `docs.yml` GitHub Actions workflow builds the site and deploys it to GitHub Pages on push to `main`.

**Tech Stack:** VitePress 1.x (Node 20), npm, GitHub Actions (`actions/upload-pages-artifact`, `actions/deploy-pages`).

## Global Constraints

- Site is a **VitePress project rooted at `docs/`**; config at `docs/.vitepress/config.ts`.
- `base: '/matterhorn/'` (GitHub project pages sub-path).
- `srcExclude: ['superpowers/**']` — internal specs/plans never published.
- Deploy trigger: push to `main` touching docs sources; workflow separate from `release.yml`.
- Content is a **restructure of the existing README** — do not invent product facts; source prose from `README.md`.
- Node 20, npm, committed `package-lock.json` (CI uses `npm ci`).
- Work in an isolated **git worktree**.
- Pre-existing uncommitted `.dockerignore` WIP must NOT be swept into any commit.
- No Co-Authored-By / co-author trailer on any commit.
- Spec: `docs/superpowers/specs/2026-07-04-vitepress-docs-github-pages-design.md`.

### Task 4: GitHub Pages deploy workflow

**Files:**
- Create: `.github/workflows/docs.yml`

**Interfaces:**
- Consumes: `package.json`/`package-lock.json` (Task 1) for `npm ci`; the
  VitePress build output at `docs/.vitepress/dist`.
- Produces: a Pages deployment on push to `main`.

- [ ] **Step 1: Create `.github/workflows/docs.yml`**

```yaml
name: docs

on:
  push:
    branches: [main]
    paths:
      - 'docs/**'
      - 'package.json'
      - 'package-lock.json'
      - '.github/workflows/docs.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run docs:build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: docs/.vitepress/dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/deploy-pages@v4
        id: deployment
```

- [ ] **Step 2: Verify the workflow is valid YAML**

Run: `python -c "import yaml; yaml.safe_load(open('.github/workflows/docs.yml')); print('ok')"`
Expected: prints `ok`.

- [ ] **Step 3: Commit (exclude .dockerignore WIP)**

```bash
git add .github/workflows/docs.yml
git commit -m "ci: build and deploy VitePress docs to GitHub Pages"
```

## Post-implementation (manual, once the repo exists on GitHub)

1. GitHub → Settings → Pages → **Source: GitHub Actions**. Required before
   `docs.yml` can publish.
2. Push `main` (or trigger `workflow_dispatch`) → the `docs` workflow builds and
   deploys → site live at `https://dirnei.github.io/matterhorn/`.
3. If a custom domain is added later: set `base: '/'` in `config.ts` and add a
   `CNAME` file under `docs/public/`.
